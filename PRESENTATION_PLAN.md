# План презентации проекта

Логика: от общей архитектуры → к данным → к бизнес-процессам → к UI → к надежности и демо-итогу.

## 1) Adilzhan — вводная и архитектура
- `ARCHITECTURE` что это за платформа и какие сервисы входят в систему
- `DOCKER` как всё запускается через compose
- `GATEWAY` как фронт общается с бэком через API Gateway
- `AUTH` регистрация / логин / JWT

## 2) Dmitriy — инвентарь и складская логика
- `INVENTORY` остатки по SKU и по складу
- `RESERVE` резервирование товара в конкретном `Warehouse`
- `RELEASE` возврат товара обратно на склад
- `CONFIRM` финальное списание после подтверждения
- `SAFETY_LEVEL` порог запаса и алерты по low stock

## 3) Alnur — заказ и каталог
- `CATALOG` создание и поиск товаров
- `ORDER_CREATE` создание пустого заказа
- `ORDER_UPDATE` изменение статуса заказа через enum
- `ORDER_CALCULATE` расчёт суммы по товарам заказа
- `ORDER_EVENTS` связь заказа с резервированием через события

## 4) Aman — надежность, проверка и демо-фичи
- `DATA_INTEGRITY` FK / CHECK / NOT NULL
- `VALIDATION` проверки на gateway и в сервисах
- `CLEANUP` удаление просроченных reservation
- `OBSERVABILITY` health, metrics, readiness
- `FRONTEND` удобный интерфейс и демонстрация всех экранов

## Рекомендуемый порядок показа на демо
1. `AUTH` → войти в систему
2. `CATALOG` → создать SKU
3. `ORDER_CREATE` → создать пустой заказ
4. `RESERVE` → добавить товар в заказ
5. `RELEASE` → уменьшить количество
6. `CONFIRM` → подтвердить списание
7. `SAFETY_LEVEL` → показать low stock и алерт
8. `DATA_INTEGRITY` → объяснить защиту данных
9. `OBSERVABILITY` → показать health/metrics

## Короткий финал
- `RELIABILITY` система защищает данные и не ломается на ошибках ввода
- `SCALE` сервисы разделены и готовы к росту
- `DEMO` все ключевые сценарии можно показать за один проход
